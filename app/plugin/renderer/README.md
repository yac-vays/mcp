# Renderer Plugins

A renderer plugin teaches the MCP server what a VAYS renderer *does to the
stored value*, so agents get the same result as VAYS users. Only renderers
that compute or transform the value need a plugin (generate, hash, encrypt).
Purely presentational renderers (`ssh_key`, `limit_bar`, `template_text`, ...)
need none: values of fields without a plugin are taken verbatim.

The file stem is the `vays_options.renderer` name the plugin handles
(`age_secret.py` handles `renderer: age_secret`). All python files are
included, there is no registration. Additional plugin roots can be configured
with `YAC_MCP_PLUGIN_DIRS` (each with a `renderer/` subdir, e.g. mounted from
a ConfigMap); a later plugin with the same name overrides an earlier one.

Plugins may only import the standard library, `app.model.plg` and packages
in the image's `requirements.txt`.

## Contract

Module-level names (only `prepare` is required):

| Name | Purpose |
|---|---|
| `prepare(ctx) -> Keep() \| Set(value, report={}) \| Unset() \| Error(message)` | Decide the value to store for one field. May be `async`. Exceptions are turned into an `Error`. `Set.report` is shown to the agent and must never contain a secret unless `ctx.reveal_secrets` is true. |
| `describe(options, schema) -> str` | Short note for the agent (shown with the schema), e.g. how to request a new value. |
| `ACCEPTS_SECRET = True` | The field may receive a cleartext via the tool's `secrets` argument (`ctx.secret`). Others reject `secrets`. |
| `TEST_VECTORS` | List of `(ctx_kwargs, check)`: the test suite builds a `RendererContext` from the kwargs (plus defaults), runs `prepare` and asserts `check(result)` is true. Runs for every loaded plugin. |

The context (`app.model.plg.RendererContext`) holds: `operation` (`create` /
`edit`), `loc` (e.g. `#/users/0/pw`), `pattern` (`#/users/*/pw`), `renderer`,
`options` (`vays_options.renderer_options`), `schema` (the field's schema
node), `agent_value` (what the agent wrote, `MISSING` if absent), `current`
(stored value at `loc`), `stored_values` (all stored values of the field),
`secret` and `reveal_secrets`, plus the helpers `generate_requested` (the
agent wrote `~generate`), `agent_value_empty`, `has_current`,
`is_stored_value`, `has_default`, `in_array` and `random(alphabet, length)`.

The core runs the plugins on the agent's YAML after the schema defaults were
filled in, before validation. Each field is processed once per tool call.

## Example

```python
from app.model.plg import Keep, RendererContext, Set


def describe(options: dict, schema: dict) -> str:
    return 'Generated by the server when empty; write "~generate" for a new value.'


def prepare(ctx: RendererContext):
    if ctx.generate_requested or ctx.agent_value_empty:
        return Set(ctx.random("0123456789", 6), {"generated": True})
    return Keep()


TEST_VECTORS = [
    ({}, lambda r: isinstance(r, Set) and len(r.value) == 6),
    ({"agent_value": "123456"}, lambda r: isinstance(r, Keep)),
]
```
